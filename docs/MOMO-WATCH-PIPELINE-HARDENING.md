# MOMO 监听与发送减法重构：第一轮

本轮针对 2026-11-02 的真实故障，运行档案：`.local-output/momo-watch/run_20261102132731_r5ie`。修复范围为旧流水线的几个关键副作用边界，**不添加状态机框架、控制通道、重试队列或新的业务错误分类体系**。

## 原始根因与实际变更

1. **联系人列表坐标过期**：原监听在识别未读后先截图，再沿用旧候选坐标点击，甚至自动补点。现在点击前再取得新列表画面、唯一匹配未读联系人并**只点击一次**；画面变化就跳过，不猜测位置。仍需处理同名联系人的稳定 ID：现有云机界面只暴露昵称，无法凭一个昵称证明两个账号相同。
2. **错误联系人的聊天入库**：`src/tools/momo/contact-sync.js` 原逻辑读取顶栏，却以传入的 `contactName` 写库。现在识别到顶栏与目标不符就中止采集；在 SQLite 提交前再读取新截图验证目标，若因顶部横幅或渲染过渡未识别到顶栏文字则轻量重试一次，最终仍无法确认就**不写入任何消息**。监听器只有在首次入库成功时才会启动 AI 回复；关键 `contactName` 和控制租约在 13/14 调用中由监听器最后指定，不允许可选参数覆盖。历史证据 `momo-sync/run-Zbfnm1/0001-initial.json` 记录目标 `Destiny`、顶栏 `ghgg`，新闸门应拦截该场景。
3. **OCR 放行了错误草稿**：删除相似度仅 0.4 即放行、任意非空粘贴视为成功、候选失败后的剪贴板猜测及多层中间兜底。现在仅在完整草稿经规范化的文字**一致**时进入发送（剥离末尾闪烁光标如 `|`、`_` 等非文字伪影，防止真机聚焦时光标误杀正确草稿）；候选词找不到或 OCR 无法核实则停止本条发送。撤销剪贴板的风险分支前，已确认本 SDK 控制 API 只有 `paste/setClipboard`，没有可靠的 `injectText` 接口。不能未经真实能力验证就冒充 Unicode 原生文本输入。
4. **软键盘空间键被当成第二个输入框**：模型已经给出了主 `input_box`，但原解析器再遍历所有候选并因第二个形似输入框就拒绝整帧。现在删除这段两两 IoU 否决，仍严格检查模型选定的返回键/输入框结构、尺寸与位置。
5. **发送后 OCR 不可靠**：点击发送后即使 OCR 无法确认输入框清空，也只返回 `uncertain`，不会当作 `not_started` 或自动重发。异常发生在已点击发送之后也按未知状态处理（控制中断仍向外抛出）。旧的 `newOwnBubble` 仍采用文字匹配，本轮**没有**将“气泡颜色变化”等同于文本已送达。
6. **单联系人错误把全局监听杀掉**：取消三次单联系人打开/回复失败的累计熔断；原有设备掉线、观测失败、风控页面的全局退出规则仍在。当前联系人只按 `done / skip / review` 处理。处于 `review` 的联系人写到**已有**按设备隔离的 `watch-ignored-cards.json` 中，跨进程重启保持隔离；人工核对发送截图与历史后删除该项才可继续。不要用计时器在缺乏证据时自动放行。
7. **截图覆盖**：AI 回复输出改用本次联系人处理的独立 `contacts/<时间戳>_<昵称>/ai-reply/`，避免同名联系人第二次尝试覆盖首次的截图、模型调用记录。

## 真机前必须做的事情

- **现有数据库脏数据未清理**：设备本地 SQLite 中 `Destiny` 和 `ghgg` 仍可能保留交叉入库消息。上线前需人工备份、核对、纠正相关记录。代码阻止新数据错写，**不会自动修好历史数据**。
- **待复核隔离人工解除**：`watch-ignored-cards.json` 中 `reason=send_pending_review` 的条目表示可能已发送但结果未确定。核查实际消息后由操作者手动删除该条；不能直接重新发送原回复。其他因非聊天页面被忽略的条目保留原行为。
- **尚未端到端验收**：禁止未经许可直接在生产云机上测试点击、输入、发送或自动拉黑。现阶段只能给出源码验证、实际旧证据检查结果；完全成功与真实发送成功须在授权测试云机上观察。
- **中文输入的限制**：现有 OCR 不能百分百读清光标、截断或小字。严格核验可能降低发送通过率，但不会再因为“非空”把部分文本视为正确。后续要先验证云机是否暴露稳定的 Android 原生输入/文本回读能力，再决定是否替代拼音输入。
- **气泡确认的限制**：当前发送后仍用 OCR 的 `newOwnBubble` 判断消息内容，错字可能产生“待复核”。只有独立可靠的气泡增量及内容证据才能进一步提升“已完成”判定，不能通过降低内容匹配阈值伪造成功。
- **部署**：该改动位于 Node 服务端和自动化代码，需在任务停止、用户连接允许时安全重启 Node 服务后加载。禁止在活跃任务时重启。

## 研发参考

- scrcpy 控制消息及文本输入：[官方控制文档](https://github.com/Genymobile/scrcpy/blob/master/doc/control.md) 和 [Controller](https://github.com/Genymobile/scrcpy/blob/master/server/src/main/java/com/genymobile/scrcpy/control/Controller.java)，明确文本注入与剪贴板是不同命令。本项目的控制通道当前只有后者。
- Appium UiAutomator2：[官方仓库](https://github.com/appium/appium-uiautomator2-driver)，可将 UI 元素文本与键盘状态作为结构化证据；但本项目尚未验证云机提供该驱动权限/通道，不直接引入。
