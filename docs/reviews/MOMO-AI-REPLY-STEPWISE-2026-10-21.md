# MOMO AI 回复逐项修复与验证记录

日期：2026-10-21。范围：用户要求逐个复现并修复上一轮确认的问题。

本轮没有新增或运行单元测试，没有调用 Claude，没有调用回复 API，也没有向联系人发送消息。验证使用真实历史截图、原数据库的隔离副本、现有 GPU 服务及 SDK 实机非发送操作。

## 1. 系统提示参与对齐和上下文

修复前：解析器已把状态条标为 `system`，读取层仍把它混入对齐；旧库又把两条状态提示保存成 `peer/self`，导致 `no_overlap`。

修复后：统一用 `isConversationMessage` 过滤可见消息、归档消息、导入和写入的数据及 API 上下文。过滤依据为原系统标志或完整时间/关注/火花提示结构，不使用普通正文关键词包含匹配。

验证结果：

- 原库中“稳重大白”的9条记录仍保留，未清理或重排；该设备全库仍为33条，修改时间未变。
- 隔离副本导入7条真实对话，两条状态提示不进入 AI 历史。
- 原失败截图恢复 `aligned`，重叠1条，新增0条。
- 把识别到的系统提示交给增量写入，新增记录数为0。
- 已导入9条的历史数据库读取时返回7条有效消息，已有序号保持不变。
- 最终真实截图复验又发现火花小图标被读成尾部标点，得到 `已连续互聊2天，“`。补齐完整状态句后的有限标点容错，仍不接受尾随普通正文。

隔离副本：`.local-output/momo-ai-reply/verification-4F3Irr/momo.sqlite`。

## 2. 换行后的孤立单字漏识

修复前：整块文字检测漏掉第二行的“过”；简单扩大裁剪又会把右侧表情按钮识别进正文。

修复后：添加经过参数校验的可选 `input_full_roi`，覆盖完整文字行并避开表情控件。备用路径按像素提取真实文字行，清理窄竖蓝色光标后直接识别；仅接受各行置信度不低于0.8的结果，不向识别器提供预期文字。

真实截图结果：

- `diagnostic-input-mismatch.png`：`哈哈谢谢夸奖，不过`，两行置信度约0.927、1.000。
- `after-correct-candidate-tap-2.jpg`：`哈哈谢谢夸奖，不过我`，约0.927、0.974。
- 空输入截图仍通过原占位文字和无发送按钮的判空条件。

## 3. 实际输入中额外复现的两个底层问题

- 第一轮实机输入停在候选“不”：上方拼音 `bu` 与候选字共享横向位置，被原列分割合成一个高框。修复为先分候选行，再做列分割。失败截图复验得到“不”，置信度约0.998，点击点来自实际识别框。
- 后续实机输入碰到表情推荐动画覆盖输入框，模型暂时缺少 `input_box`。增加最多三次新截图识别；不复用旧框、不放宽模型条件。实际输入随后成功。

实机已连续两轮完整输入并严格校验 `哈哈谢谢夸奖，不过我`，分别耗时约13.8秒、12.9秒，均未发送。截图：`.local-output/momo-ai-reply/live-typing-srz8qf/verified-draft.png` 和 `.local-output/momo-ai-reply/live-typing-l3MOYD/verified-draft.png`。每轮结束后均清空本轮输入并确认空框，随后收起键盘。

## 4. 键盘挤出旧锚点后的发送确认

修复前：发送前只看到对方末条消息，发送后只看到己方新气泡，不能对齐。

修复后：只有在已确认输入框清空、当前仍为目标聊天页、键盘展开、已看到完全匹配的己方文字且结果为 `no_overlap` 时，才发送一次 BACK 收起键盘。恢复后仍须旧锚点重叠，且恰好新增一条预期的己方消息；不满足仍为 `uncertain`。

展开可视区域可能露出更早消息。只有明确记录过恢复且当前键盘确已收起时，发送证据比较才允许在不同可见起点寻找旧锚点；所有有效对齐必须指向同一个旧/新消息边界。出现两个不同边界或重复锚点歧义时拒绝确认，不能截掉中间新消息来凑出最后两条。恢复标记与发送证据一起持久化，供只读复核使用。

实机验证：在“稳重大白”聊天页收起键盘一次，旧锚点重新可见。以真实历史发送前截图和恢复后的实际画面复核已发送的 `哈哈谢谢夸奖，你嘴真甜`：原方式不能确认，恢复方式可以确认。本轮没有再次发送这句话。

截图：`.local-output/momo-ai-reply/live-expanded-7u73ku/keyboard-closed.png`。

- 正式调用 `runMomoAiReplyOnce` 的 `observe` 模式，连接实际设备，写入隔离数据库副本，返回 `completed / observed_only`。
- 正确识别新增己方消息1条，新增对方消息0条，没有触发回复。
- 修改过的 JavaScript 通过 `node --check`；Python 通过 AST 语法检查。
- GPU 服务已重载到本轮代码，设备为 RTX 3060 / `cuda:0`。
- 本轮启动4318控制台的尝试被环境策略拦截；没有绕过策略。SDK 验证不依赖该网页进程。
