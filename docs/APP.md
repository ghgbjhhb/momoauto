# 云手机脚本控制台

本地系统壳：左侧集中预览云机，点击屏幕进入放大的手动操作窗，右侧保留现有脚本按钮。当前是本机测试版本，不是已经完成账号隔离、授权与升级体系的商业发行版。

## 启动

本机当前网页登录 Cookie 中的登录令牌已导入 `.env.local`。正常启动不再要求手工填写 CK / Token：

~~~powershell
npm run app
~~~

然后打开 [本地控制台](http://127.0.0.1:4318/)。顶部显示“网页登录态已就绪”后会自动加载设备。服务重启仍读取本地会话；网页 Cookie 以后过期或切换账号，不会自动跨浏览器读取新的 Cookie，需要重新同步，不能把“本地已保存”当成永不过期。

本机默认使用已保存的 `.runtime/certificates/default-keybox.xml`，路径记录在忽略发布的 `.env.local`，不需要每次启动前手工设置。证书不在网页静态目录，也不应放进销售安装包或公开仓库。需要临时替换时，仍可在启动前指定证书路径：

~~~powershell
$env:YUNMOMO_CERT_PATH = 'C:\path\to\keybox.xml'
~~~

统一入口为 `http://127.0.0.1:4318/`，`npm run app` 默认启动此地址，不再另开旧控制台。只允许本机回环地址，不开放公网；特殊部署仍可用 `YUNMOMO_APP_PORT` 显式覆盖端口。HTTP 与 WebSocket 拒绝其他网页 Origin。云端凭据留在 Node 服务端，不通过截图 / 手动控制接口回传前端，不放在浏览器 localStorage 或 WebSocket URL 中。脚本由本地 Node 进程按原有白名单启动，输出脱敏。

未配置 / 已过期时才显示折叠的“会话设置”备用入口。导入先向云端验证，不用错误值覆盖有效会话。配置优先级为本进程新导入会话 → `YUNMOMO_TOKEN` 环境变量 → `.env.local`；新进程若显式设置了旧环境变量，会优先于文件，请清除过期环境变量。

`.env.local` 是本机明文凭据文件，不是加密保险箱，已在 `.gitignore` 忽略，且不在 npm 发布文件白名单中。不要放入销售安装包、截图、源码包或公开仓库，也不要复制给客户。浏览器只保存屏幕大小偏好，不保存 CK。客户登录 / 本机安全存储和商业授权属于后续发布工作。

## 页面功能

- 顶部刷新设备列表；设备详情有 3 秒短缓存，避免每张截图重复请求完整列表。
- 左侧显示账号云机，H.264 视频由本地后端原样转发，浏览器持续解码播放。没有 1.8 秒截图轮询；同台观看连接共享一个上游。失败保留最后画面并标记“待刷新”，预览间隔 3 秒尝试重连，不重放输入。
- “屏幕大小”支持 140–280 的卡片最小宽度，默认 190，实际宽度随网格分配；更小的值可在当前 1280px 窗口内一行显示 5 台。偏好在当前浏览器保存。手机画面保持比例，不做额外压缩；桌面窗口高度自适应，列表内部滚动，小屏改为上下布局。
- 点击卡片标题选择脚本目标；点击屏幕放大并同时选择该设备。设备编号加 ID 尾号用于区分重名设备，后台仍使用真实 deviceId，不把编号当作 ID。
- 右侧按既定顺序显示 01–08、改机重置、增加VPC网络及执行全部；使用原定脚本名称，执行全部仅运行 01–08。
- 设备脚本先选择云机再执行；增加VPC网络为账号级操作，改机重置保留清数据确认。本次高清画面修改没有自动运行任何业务脚本。
- 运行中的脚本可停止；控制台等待脚本进程退出后才释放设备占用。停止会终止当前进程，不保留可恢复的暂停点；中断后请核对设备状态。
- 证书上传只保留一个入口，目标就是当前选中的云机，不再区分第一台、第二台或第三台。

## 放大后手动操作

点击左侧某台屏幕，会打开适应窗口的放大画面，保持手机原图比例，黑边不参与触控。放大窗复用设备卡片当前的解码画布；触控通过独立输入连接发送，不再额外解码一份相同的视频。原预览断开时才在放大窗建立只读视频连接作为备用。控制状态显示就绪后支持：

- 鼠标单击、按住、拖动；浏览器捕获指针，拖出画面后也会松开触点。
- 鼠标滚轮滚动，以及“返回 / 主页 / 最近任务”三个导航按钮。
- 先点击手机画面聚焦，再用英文键盘逐键输入；空格、回车、删除、方向键与常用标点按键会发给手机输入法。电脑本地输入法应切到英文，中文组合输入和 Ctrl/Cmd/Alt 快捷键不转发，也不偷偷使用剪贴板粘贴。
- Esc 关闭；失焦、隐藏页面、取消拖动、连接关闭和输入闲置 10 秒时，尽力松开触点 / 按键。瞬时断线自动恢复视频连接，绝不重放操作；重新收到实际画面之前不接受新输入。

坐标按视频实际显示区域去除黑边，再归一化映射到 SDK 当前控制尺寸；宽高比不一致时停止触控。画面未就绪或最近显示帧的本地接收时间超过 6 秒时不接受新动作。该时间不是设备采集时间戳，不包含上游缓冲。隐藏页面仅释放输入并清除输入用的画面时间，不关闭投屏；回来后丢弃旧帧并请求关键帧。手动窗口断线按 1.5、3、6、12、24、30 秒上限退避重连，收到新画面后重置退避；关闭窗口取消重试，旧连接不能恢复已结束的会话。设备被占用、连接配额或编解码不支持等错误不自动重试。

手动控制期间，该设备不能运行控制台脚本；同一设备可以在多个本地网页同时打开，操作按服务端收到的先后顺序执行。触点和按键由最后操作它的网页接管，避免不同网页交错按住同一个输入。只有关闭该设备的最后一个手动窗口才会释放占用；脚本运行中不能开手动窗。此互斥仅覆盖本控制台，不会协调云端官网或其他独立 SDK 进程。

## 画面与接口

控制台使用 `云手机 → Node 后端 → 浏览器 WebCodecs → Canvas`。当前默认编码器配置为 8,388,608 bit/s 码率、15 帧/秒上限、1 秒关键帧间隔；初始化元数据包含有效物理显示尺寸时，视频尺寸上限按设备实际显示尺寸设置，否则回退到 720×1280。实际输出仍由云端、网络和浏览器决定，页面收到的 `ready` 状态会报告协商后的配置和实际屏幕尺寸。后端不解码或重编码显示视频，不传云端 Token、UDID、连接 URL 或初始化协议数据到视频接口。浏览器不直连云端；鼠标、键盘继续由后端校验和转发，后续用户鉴权与设备授权应放在该入口。

同台预览与手动输入共用上游连接；放大时把所选设备正在播放的画布移进操作窗，触控只占用输入连接，不增加视频观看者或浏览器解码器。其他设备的预览保持连接，关窗后画布回到卡片；只有原预览断开时，放大窗才临时建立只读视频连接。每个后端最多 16 台视频，每台最多 8 个视频观看连接。单个观看客户端积压超过 4MiB 就关闭该客户端，不拖住其他观看者；10 秒不回应 WebSocket ping 则终止并释放占用。浏览器解码队列超过 16 个时等待新关键帧恢复，不继续展示积压的旧视频；绘制仅保留最新解码帧。编解码配置或浏览器不支持时明确返回错误，不回退到低帧率截图。

静止画面会自然停发视频，后端仅重新配置编码器取得新帧，不发送点击、导航或键盘。浏览器优先请求硬件解码，具体是否使用硬件由浏览器和设备能力决定；15 帧/秒是网页直播的编码器配置上限，不代表实际画面始终达到该帧率。Annex-B、SPS/PPS 和关键帧处理按 [W3C H.264 WebCodecs 注册说明](https://www.w3.org/TR/webcodecs-avc-codec-registration/) 实现。

### 无操作保活与画面卡死恢复

4318 使用本项目 SDK 视频转发，不运行云端官网的投屏组件，也不读取官网 `streamIdleSleepMin` 设置。项目不设“10 分钟无鼠标操作就休眠”的规则，不通过虚假点击、按键、静音音频或改浏览器全局参数保活。

- 后端每 15 秒向云端 WebSocket 发协议 ping；10 秒收不到 pong 则关闭失活上游，前端再建立新连接。本地写入成功不等于对端已响应。
- 持续 6 秒没有上游视频包时才请求一次编码器刷新，服务端对刷新统一做 10 秒冷却；观看者接入和 `size` 元数据不会触发刷新。编码器重配置后，浏览器只清空旧解码参考链并等待关键帧，避免新旧编码代次混用。持续 30 秒无帧则关闭卡住的上游。页面可见时，首帧 / 切回后首帧等候超过 15 秒，或已播放画面超过 20 秒未更新，也会触发重连；JSON 心跳不能充当视频帧。
- 标签页隐藏不再主动关闭预览、输入或手动投屏连接，后台不积存待绘制 VideoFrame；切回时重建解码状态、等待关键帧，不回放后台积压画面。返回页面和网络恢复事件也会补建缺失的订阅。
- 浏览器自身仍可能降低后台绘制频率，或在系统休眠、标签页被丢弃时断开连接；网站不能承诺绕过这些系统行为。此实现保持项目连接并恢复画面，不保证后台同样按 30 FPS 绘制。

保活会持续使用视频网络流量及云端连接资源；最后一个视频观看者和输入持有者都结束后才释放上游，而不是等无操作超时。输入闲置 10 秒松键保护是另一套安全机制，不影响视频连接。

显示视频不需要 FFmpeg。原 `GET /api/screenshot`、SDK 和识别工具的高清 PNG 路径保留，只有调用这些取图接口时才启动其独立解码进程；该路径仍需要系统 FFmpeg 或 `YUNMOMO_FFMPEG_PATH`。识别不使用缩小后的网页截图。

截图解码器启动失败独立返回 `DECODER_NOT_FOUND` / `DECODER_START_FAILED`，包括进程创建时同步抛出的错误，不再误报为云端连接失败。

`GET /api/screenshot` 返回 `X-Screenshot-Source: stream`、`X-Image-Width`、`X-Image-Height`、`X-Frame-Decoded-At`。最后一个字段仅为本机解码时间，不是设备采集时间。SDK 与底层工具的独立高清调用、依赖和错误码见 [高清截图](HD-SCREENSHOT.md)。

控制桥只接收有界坐标、白名单按键 / 导航、滚动和释放，不提供任意 SDK 方法、脚本或 shell 透传。超过 4KiB 的消息或过快输入会拒绝；输入失败反馈错误，不宣称手机已执行。现有 SDK 采用云端 WebSocket 协议，不需要安装 ADB、Root 或 OCR。高清 PNG 解码需要 FFmpeg，不新增 npm 依赖。

视频 WS 二进制消息是原 H.264 包；JSON 消息类型包括 `size` / `ready` / `heartbeat` / `error` / `input_reset`。`ready` 报告实际屏幕尺寸及编码器帧率、码率和尺寸上限。`/api/control-input` 只传 JSON 手动输入和状态，不传视频包。浏览器可发送 `{ "type": "refresh" }` 请求编码器刷新，后端统一做 10 秒冷却；`size` 只用于清理浏览器旧解码参考链，不会再次请求刷新。原手动 JSON 输入格式保持不变。错误定位包含 `VIDEO_CONNECT_FAILED`、`VIDEO_CONNECTION_LOST`、`VIDEO_PROTOCOL_ERROR`、`VIDEO_DISCONNECTED`、`VIDEO_BACKPRESSURE`、`VIDEO_PACKET_INVALID`、`VIDEO_REFRESH_FAILED`、`VIDEO_LIMIT`、`VIEWER_LIMIT`，另增 `VIDEO_UPSTREAM_TIMEOUT`（云端未响应 ping）和 `VIDEO_UPSTREAM_STALLED`（云端持续无帧）；浏览器另有 `VIDEO_DECODER_UNSUPPORTED`、`VIDEO_CODEC_UNSUPPORTED`、`VIDEO_FRAME_TIMEOUT`（连接消息超时）、`VIDEO_FRAME_STALLED`（显示画面停止更新）、`VIDEO_DECODER_FAILED`、`VIDEO_DECODE_FAILED`、`VIDEO_RENDER_FAILED`。视频断线和输入连接断线分别恢复，不重放手动输入。用户系统尚未实现，当前仍是本机同源和当前云账号设备归属校验。
